# 디자인 시스템 개편 (2026-11-20): 「밤티」를 뿌리에서 걷어 내기

그림: [`design-overhaul-2026-11.png`](design-overhaul-2026-11.png) (위 = 고치기 전, 가운데 = 고친 뒤, 아래 = 100% 크롭과 팔레트 12벌)

주인 피드백 셋. ① 결과물이 아직 「밤티」다(AI가 만든 티). ② 결과가 너무 템플릿 같다. ③ 재료가 전문가가 만든 느낌이어야 한다.
그래서 결과물 하나하나가 아니라 **무기들이 같이 쓰는 디자인 시스템**(`shared/design`, `shared/shell`, `shared/fonts`)을 고쳤다.
기준은 주인이 승인한 연수 덱의 「먹과 놋쇠」 규칙(`docs/training/deck-v2-harness-notes.md` 7~9절)이다.

## 3. 「템플릿 같다」: 뼈대가 내용과 시드를 따라가게

- 게임: 문제 화면 배치를 **내용**으로 고른다(OX 비율, 보기 길이, 문제 길이, 그림 유무: `layout_auto.content_features`). 스타일의 취향은 한쪽으로 쏠리지 않게 눌러서(가중치 0.6제곱) 같은 요청도 시드가 다르면 다른 뼈대.
- 프로그램: 부품 수·종류·설명 유무로 배치를 고른다(`build_webapp.pick_layout`: focus·aside·wide / cols2·lead2·stack / cols3·lead3·stack, 머리는 bar·hero·rail). 예전에는 한 가지였다.
- 발표: 원래 장마다 내용 조건으로 배치를 골랐다. 이번에는 배경 무늬가 시드와 장 번호를 따라 자리(모서리·줄 위치·판 개수)를 바꾼다.
- 배경: 게임 배경 8종도 시드에 따라 구도가 바뀐다(어느 모서리, 판 몇 장, 줄이 위냐 아래냐).

### 비슷함 점수 (낮을수록 서로 다름)

게임 = `design_review`의 문제 화면 지문 겹침(0~1), 발표 = `slides_review.distance`를 뒤집은 값, 프로그램 = 발표와 같은 식(스타일 0.4 + 배치 0.3 + 강조색 0.3)을 프로그램 뼈대에 적용.

| 무기 | 묶음 | 고치기 전 | 고친 뒤 | 읽는 법 |
|---|---|---|---|---|
| 게임 | 서로 다른 요청 3개 | 0.553 | **0.812 (나빠짐)** | 세 개 중 둘이 같은 bento 배치로 뽑혔다(0.968). 표본 3개라 흔들림이 크지만, 이 점수로는 **좋아지지 않았다** |
| 게임 | 같은 요청 x 시드 3개 | 1.000 (1쌍만 측정) | 0.896 | 전: 둘 다 `minimal-premium/poster`로 똑같음. 후: `tv-gameshow/news` · `minimal-premium/bento` · `minimal-premium/poster`로 스타일·배치는 달라졌으나, 칸 겹침 지문은 여전히 높다(0.84~1.0) |
| 발표 | 서로 다른 요청 3개 | 0.008 | 0.032 | 원래 충분히 달랐고 그대로다 |
| 발표 | 같은 요청 x 시드 3개 | 0.201 | 0.231 | 원래 시드마다 스타일·배치가 달랐고 그대로다 |
| 프로그램 | 서로 다른 요청 3개 | 0.346 | 0.306 | 조금 나아짐 |
| 프로그램 | 같은 요청 x 시드 3개 | 1.000 | **0.794** | 전: 시드와 무관하게 완전히 같은 뼈대. 후: `aside+bar` · `focus+hero` · `wide+rail`. 색·스타일은 예시의 낱말(「깔끔」)이 고정해서 같다 |

정리: **프로그램은 뼈대가 실제로 갈라졌고, 발표는 원래 괜찮았고, 게임은 이 점수로는 개선을 보이지 못했다.** 게임 지문은 「카드와 큰 글자가 덮은 칸」만 보기 때문에
배치 이름이 달라도(bento·poster) 덮는 넓이가 비슷하면 같게 나온다. 게임을 정말 다르게 하려면 배치 5종의 기하(`layouts.css`의 자리)를 더 벌려야 한다. 다음 손질 대상이다.
측정 중 `--review`(디자인 검토 관문)를 켠 게임 6개 가운데 2개는 고치기 전에도 뒤에도 NOT READY였다(검토 관문 쪽 문제, 일반 점검은 통과).

### 사실상 틀로 굳은 예시 (내용은 건드리지 않았음, 다음 손질에서 볼 것)

- 게임 예시 스펙 여러 개에 `design.seed`가 박혀 있다(`e-family-quiz` 6, `j-tv-quiz-dokdo` 21, `a-escape-light-wave` 1). 예시를 베끼면 생김새까지 그대로 따라온다.
- `j-tv-quiz-dokdo`의 낱말 「방송국」「퀴즈쇼」는 옛 장면 테마 `tv-studio`를 통째로 부른다. 퀴즈쇼 요청이 이 예시를 베끼면 늘 같은 스튜디오 장면이 된다.
- 프로그램 예시가 둘뿐이고 둘 다 낱말에 「깔끔」이 있다(`coding-helper`, `speed-sim`). 그래서 프로그램은 거의 늘 「에디토리얼」 아니면 「먹빛 테크」로 나온다. `speed-sim`의 화면 폭을 다 채운 검은 버튼도 예시의 `html`에 들어 있는 것이다.
- 공공 발표 예시(`public-*`)는 표지 → 목차 → 요약 상자 순서가 맥락 레시피로 고정이다(의도된 고정이지만 틀처럼 보이는 원인).
- `promo-school-festival`의 사진 자리에 든 그림(`photos/`)이 형광 보케다. 덱은 차분해졌는데 예시 사진만 옛 느낌이다.

- 스킨 17개를 `studio.py fire`로 다시 만들고 `check`: **17개 모두 PASS, 경고 0**.
- 예시 스펙: 게임 12개 READY(처음에 `f-sort-recycle`이 「30px 글자」로 FAIL → 틀린 문제 목록 글자를 34px로 올려 PASS), 수업 도구 5 · 프로그램 2 · 문서 6 READY.
- 발표 예시 13개: 10개는 FAIL 0(브라우저 열기 점검은 `--review` 없이는 원래 건너뜀). **3개(`photosynthesis` · `parents` · `public-ai-edu-report`)는 「JavaScript syntax」 FAIL인데, 고치기 전 커밋에서도 똑같이 FAIL이다**(차트 부품 Chart.js 안의 문법을 문법 점검기가 못 읽음). 이번 작업 범위 밖이라 손대지 않았다.
- 단위 테스트 22개 파일 모두 OK(새 파일 `tools/test_design_system.py` 25개 포함). 옛 구현에 묶여 있던 단정 2개는 새 사실에 맞게 고쳤다(기본 글꼴 이름, 퇴역한 배경 이름).
- `tools/sync_shared.py` → `--check` OK(복사본 696개, zip 일치), `scripts/setup.py --agent claude-code` 완료.
- 화면은 헤드리스 브라우저 캡처로만 봤다. 실제 전자칠판·빔 프로젝터에서 색과 글자 굵기가 어떻게 보이는지는 사람이 확인해야 한다.

## 5. 남은 것 (정직하게)

- 옛 장면 테마 9개(TV 스튜디오, 우주 정거장 등)의 **캔버스 그림 자체**는 다시 그리지 않았다. 색(형광 제거)·빛 번짐·글꼴만 고쳤다. 무대 조명 빔 같은 그림 요소는 남아 있다.
- 엔진 안 옛 기본 테마 표(`engine.html`의 arcade·space 등)는 그대로 두고, 그 위에 공통 마감 층이 덮는다. 엔진을 직접 다시 쓰는 일은 다음 차례.
- PPTX(파워포인트 파일)의 글꼴은 그대로 Noto Sans KR/맑은 고딕이다. 받는 PC에 없는 글꼴을 파일에 심을 수 없어서다.
- 「전문가 급」인지는 그림으로 판단해야 한다. 100% 크롭을 시트 아래에 붙였다. 프로그램 화면과 방향 카드는 아직 발표·게임만큼 다듬어지지 않았다.
- 움직임 값은 시스템과 CSS 변수로 내보냈지만, 게임·발표의 기존 움직임 코드를 그 값으로 모두 바꾸지는 않았다.
