# deck-v2 움직임 · 그림 점검 (2026-11-20)

「모션이나 그래픽 어색한 것들도 조사해 봐」에 따라 34장 전체를 **끝 모습이 아니라 움직이는 도중**까지 찍어서 본 기록이에요.

- 열쇠 장면 모음(고친 뒤): `deck-v2-motion-qa.png` (204장: 단계마다 「움직이는 중」과 「끝」)
- 고치기 전 · 후: `deck-v2-motion-qa-before-after.png`
- 다시 돌리기: `set PYTHONUTF8=1 && py docs/training/deck-v2-src/motion_qa.py --out <빈 폴더>` → 장마다 `sNN.jpg`(단계 × 10프레임 띠)와 `metrics.json`. 그다음 `--sheet`로 모음 그림, `--reduced`로 움직임 줄이기 점검.

## 어떻게 봤나
- 브라우저는 하나만 띄웠어요. 페이지 시계를 멈추고(Playwright `page.clock`) 스크립트가 시간을 밀 때만 흐르게 해서, 소프트웨어 WebGL이 느려도 프레임마다 정해진 시각의 모습이 찍혀요. CSS 움직임은 같은 시각으로 맞춰 줬어요.
- 단계마다 10프레임: 2D 장은 0 · 80 · 160 · 240 · 340 · 460 · 620 · 820 · 1100 · 1500ms, 3D 장은 0 · 150 · 300 · 500 · 750 · 1050 · 1450 · 2000 · 2700 · 3600ms. 모두 119단계(장 34 + 빌드 85) · 1,190프레임.
- 숫자 셋: **멈추는 시각**(더는 안 바뀌는 때) · **첫 프레임 몫**(첫 80ms에 다 바뀌면 「툭」 나타나는 것) · **깜빡임**(밝기가 오르내리는 횟수/초).
- 눈으로 본 것: 띠 그림 34장 가운데 3D 장 전부와 숫자가 튄 장은 크게 확대해서, 나머지는 띠로 봤어요. 끝 모습은 1920px 사진과 모음 그림으로 봤어요.
- 한계: 소프트웨어 렌더링으로 본 것이라 **실제 PC에서의 부드러움(끊김)은 재지 못했어요.** 김치볶음밥 장과 「3번 문제의 여행」은 실제 PC에서 한 번 넘겨 보세요.

## 문제없다고 확인한 것
- **빌드 속도**: 2D 빌드 53단계 가운데 45단계가 0.34~0.82초에 멈춰요(목표 0.4~0.9초). 나머지: 4장 · 17장 첫 빌드는 두 덩이가 시차를 두고 나와 0.9초 남짓, 14장 기둥 1.1초(위 표), 18장은 타자 치는 글(약 3초, 뜻이 있는 움직임), 28장은 신호 점선이 계속 흘러요.
- **깜빡임**: 초당 3번 넘게 번쩍이는 것은 없어요(가장 큰 값 0.83회/초, 김치볶음밥 5단계의 착지 반짝임).
- **날아오는 물건**: 김치볶음밥의 레시피 · 도구 · 재료 여섯 개가 모두 제자리에 놓이고, 도장 셋(레시피 · 도구 · 재료)과 「이게 하네스!」가 누르는 순간 움직여요.
- **로봇**: 걷기 → 도리도리 → 뛰기 → 달려 나가기 → 끄덕 → 엄지척 사이에 몸이 꺾이거나 튀는 프레임은 띠에서 보이지 않았어요.
- **「하네스」 글자**: 세 글자가 떨어져 가운데에 꽂히고, 카메라가 가운데에서 멈춰요.
- **움직임 줄이기**: 119단계 모두 앞 단계와 다른 그림이에요(단계마다 내용이 전달돼요). 7장은 알약이 날아오지 않고 바로 놓여요.
- **WebGL 없음 · 휴대폰**: `shoot.py --nogl`, `--reduced --phone` 모두 PASS.
- **색 · 모서리 · 그림자**: 새 7장은 22px 모서리 · 아래로 떨어지는 검은 그림자 하나 · 가는 무광 선으로 다른 장과 같아요. 팔레트 밖 색은 7장의 브랜드 이름 두 개(Claude · Gemini)뿐이고, 이유는 `deck-v2-NOTICE.md`에 적었어요.

## 숫자 읽는 법 (`metrics.json`)
`"7.3": {"settle": 820, "first": 0.16, "flash": 0}` = 7장 3단계는 0.82초에 멈추고, 첫 프레임에 전체 변화의 16%가 일어나고, 깜빡임이 없어요. 3D 장은 카메라가 아주 천천히 계속 흐르기 때문에 settle이 늘 3600으로 나와요(이 숫자로 판단하지 말고 띠를 봐요).
