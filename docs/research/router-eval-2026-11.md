# 입구 평가 결과 (2026-11-19)

방법: `tools/router_eval.py` + `tools/router_cases.json`(요청 30개). 모델에게 **설치된 스킬 목록(이름·설명) + teacher-studio의 SKILL.md**만 주고, 첫 답을 어떻게 할지 JSON으로 말하게 했다(실제 도구는 돌리지 않음). 점수는 한 건당 1점 만점: 길 0.4 · 「먼저 보여 주기 vs 바로 만들기」 0.2 · 질문 수 0.2 · 하지 말 것 0.2. 바닥값(floor) = 여러 번 돌렸을 때 가장 나쁜 한 번의 평균, 평균(mean) = 그 평균들의 평균.

## 결론 먼저

1. **새 입구 규칙(번호 붙은 R0~R5)으로 세 모델 모두 0.98~0.99점**이다(30건 1회). 고치기 전 0.96~0.98이었고, 한 번 고친 뒤 올랐다.
2. **Haiku로 10건 × 3회 돌린 바닥값은 0.98, 평균 0.993**이다. 약한 모델도 같은 길로 간다.
3. **이 평가는 변별력이 약하다는 한계가 있다.** 길 이름과 한 줄 설명을 모든 조건에 똑같이 주었기 때문에, 스킬 없는 「맨 모델」도 0.92~0.95점이 나왔다. 하네스가 번 몫은 **+0.03~0.06**(맨 모델 대비)이고, 이전 SKILL.md(0.97~0.99)와는 **차이가 없는 수준**이다. 새 규칙의 이득은 점수보다 「SKILL.md가 139줄에서 81줄로 줄고, 약한 모델도 순서대로 따라 할 수 있다」는 구조에 있다.
4. 아직 틀리는 것: 「학부모 총회 운영 계획」(c17)·「독서 커리큘럼」(c18)은 Sonnet·Opus가 「충분히 분명하다」고 보고 방향 3가지를 건너뛴다. 기대치(막연한 요청이니 먼저 보여 주기)가 과한지 판단이 갈리는 칸이라 규칙을 더 조이지 않았다.
5. Codex는 이 PC의 사용 한도(2026-11-20 11:10까지)에 걸려 **돌리지 못했다**. 실행기는 `--models codex`로 지원한다.

## 한계 (정직하게)

- 모델이 「이렇게 하겠다」고 말한 것을 채점한다. 실제로 스크립트를 돌리고 파일을 만드는 단계의 일관성은 점검기가 따로 본다.
- 질문 수는 모델이 적은 값과 첫 답의 물음표 수 중 큰 값이다.
- 길 이름을 스키마에 적어 주었기 때문에 맨 모델 점수가 높게 나온다. 길 이름 없이 열린 답을 받아 채점하면 격차가 더 벌어질 것으로 **추정**하지만 재 보지 않았다(**확인 필요**).
- 30건을 만든 사람과 규칙을 고친 사람이 같다. 고친 규칙이 이 30건에 맞춰졌을 수 있어, 새 요청 10여 개로 다시 재는 것이 좋다.
- 1회 실행이라 모델 간 0.01~0.02 차이는 의미가 없다.

## 다시 돌리는 법

```
py tools/router_eval.py --static                                 # 모델 호출 없이 점검
py tools/router_eval.py --models haiku,sonnet,opus               # 30건 1회
py tools/router_eval.py --models haiku --runs 3 --subset 10      # 바닥값
py tools/router_eval.py --models haiku --bare                    # 스킬 없는 기준선
py tools/router_eval.py --models codex                           # Codex (로그인·사용 한도 필요)
```
참고: Windows의 `claude` 실행 파일은 한글 인자를 깨뜨려서, 시스템 프롬프트는 파일로 넘긴다(`--system-prompt-file`).
