# 저학년 수업 PPT: Claude가 스튜디오를 쓰면 지던 칸을 고친 결과 (2026-11-21)

앞 문서: [`leftovers-2026-11.md`](leftovers-2026-11.md) (그 문서의 「아직 지는 칸」). 연수 자료(`docs/training/`)는 손대지 않았다.

## 쉬운 말로 먼저

- **결론: 차이는 줄었지만 아직 이기지 못했다.** 원래 주제(2학년 「신호등 색깔과 교통안전 표지판」, 8장)에서 일반 Claude와의 차이가 -0.69 → -0.25가 되었다. 새 주제(1학년 「학교에서 만나는 안전 표지와 색깔」, 10장 정도)는 -0.25다. 두 칸 모두 ±0.3 안쪽이라 「차이 없음」으로 읽을 수는 있다. 그래도 소유자의 기준인 「스튜디오 ≥ 일반」을 확인했다고 말할 수는 없다.
- **왜 졌나 (원인 셋).**
  1. **그림 도구가 표지판을 그릴 수 없었다.** 도형(세모·동그라미·네모)과 글자만 있어서 Claude는 「노란 세모」「빨간 동그라미」를 그렸다. 안에 들어가는 그림(사람, 자전거, 아이)은 넣을 방법이 없었다.
  2. **짧은 PPT에서 「틀 장」이 내용을 밀어냈다.** 8장짜리 수업 PPT인데도 점검기가 학습 목표 장·정리 장·확인 문제 2개(문제 하나에 한 장)·활동 장이 없다고 알렸다. 여기에 정답 장이 자동으로 붙는다. Claude는 이 알림을 따라 내용 장을 3~4장으로 줄였다. GPT는 이 도구를 쓰지 않고 직접 만들어서 영향을 받지 않았다.
  3. **글씨가 작았다.** 그림 옆에 칸을 붙이는 배치에서 설명 칸이 좁아 16~17pt까지 줄었다. 그림 이름표도 작았다. 일반 Claude는 모든 글을 24pt 넘게 썼다.
- **고친 것**: 그림에 아이콘 넣기, 확인 문제 여러 개를 한 장에, 짧은 PPT의 틀 줄이기, 맨 도형·같은 말 반복·저학년 작은 글씨를 알리는 점검, 스킬 글에 기준 몇 줄. 칸을 정해 주는 틀(템플릿)은 넣지 않았다. 특정 모델만을 위한 장치도 없다.
- **좋아진 것**: 내용 점수는 이제 스튜디오가 일반보다 높다(새 주제 4.38 대 3.62). 표지판을 아이콘으로 그리는 실행이 생겼다(4개 중 3개).
- **남은 것**: 읽기 쉬움 점수(3.5~4.0 대 4.9~5.0)가 그대로다. 「글씨가 작다」는 점검 알림이 떠도 두 실행은 고치지 않고 끝냈다. 새로 만든 「한 장에 문제 여러 개」 배치도 보기 글씨가 작다는 지적을 받았다.
- **GPT는 나빠지지 않았다**: 원래 주제 스튜디오 GPT 4.81(새로 만듦)이다. 이번 측정에서 일반 GPT는 3.88~3.94였다.
- 칸마다 실행 2회, 심사 2명 × 2회다. ±0.3 안쪽은 차이로 읽지 않는다.

## 1. 원인을 어떻게 찾았나

지난 측정의 Claude 스튜디오 PPT 2개(`leftovers-2026-11/raw/runs/color-ppt-claude-harness-*`)를 일반 Claude 2개, 스튜디오 GPT 2개와 나란히 그려 보고, 만든 설명서(`deck.json`)와 글자 크기를 셌다.

| 무엇 | 일반 Claude | 스튜디오 Claude (지난 측정) | 스튜디오 GPT |
|---|---|---|---|
| 글자 수(8장) | 511 · 587 | 732 · 714 | 1130 · 996 |
| 20pt 미만 글자의 비율 | 0 % · 0 % | 11 % · 25 % | 54 % · 32 % |
| 표지판을 그린 방법 | 도형 + 그림 기호(사람, P) | 세모·동그라미·네모 + 글자 | 직접 그린 그림(사람·아이·자전거가 든 표지) |
| 내용 장 / 전체 | 5~6 / 8 | **3~4 / 8** (목표 장, 문제 2장, 정답 장) | 6 / 8 |
| 그림 옆 설명 | 없음 | 그림 이름표를 옆 칸이 되풀이(「멈춰요」 ↔ 「빨간불: 멈춰요」) | 그림이 못 보여 주는 것(깜빡이는 초록불) |

하네스 쪽에서 찾은 것:

- `diagram`은 선·도형·글자만 그렸다. 실제 물건을 「알아보게」 그리라는 기준은 없었다. 스킬 글의 「a drawing and the terms it shows belong on one slide (`panel`: `diagram` + `cards`)」 때문에 그림 이름표와 옆 칸이 같은 말을 했다.
- `deck_context.lint`는 수업 PPT가 8장 이상이면 학습 목표·정리·확인 문제 2개 이상·활동을 따로 요구했다. 8장에서 이 넷과 표지, 마무리, 정답 장을 모두 지키면 내용 장이 거의 남지 않는다.
- 저학년 글 규칙(「3 items or fewer per slide」)은 한 장의 글을 줄이라는 뜻이었다. 그런데 장 수가 정해져 있으면 단원 내용 자체가 줄어든다.
- `.pptx`의 그림 이름표는 15/19/25pt × 0.86(작은 그림)이고, 바닥은 14pt였다. 저학년 바닥(16pt)을 따르지 않았다.

## 2. 무엇을 바꿨나 (하네스만, 과제는 그대로)

| 바꾼 곳 | 내용 |
|---|---|
| `deck_diagram.py` · `deck_pptx.py` | `diagram`에 `icon` 모양을 더했다: `{"kind":"icon","name":"person-standing" 또는 "자전거","x","y","size","color"}`. 웹은 SVG 경로를 바로 넣고, `.pptx`는 고칠 수 있는 윤곽선으로 그린다. 바탕과 대비가 모자라면 색을 바꾼다. 없는 이름이면 고칠 곳을 알려 준다 |
| `deck_pptx.py` | 저학년·고학년·어르신 PPT의 그림 이름표와 도형 안 글을 1.2배로 키웠다(바닥 16pt). 그림 옆 설명 줄은 24pt |
| `deck_spec.py` · `deck_pptx.py` · `deck_layouts.py` | `quiz`에 `questions`(2~3문제)를 더했다. 한 장에 문제가 줄마다 하나씩 들어간다. 정답 장에는 모두 모이고, 발표자 메모에도 들어간다. 웹 슬라이드는 `set` 배치로 그린다 |
| `deck_context.py` | (1) 10장 이하 수업 PPT에서 내용 장이 절반보다 적으면 NOTE를 낸다(목표는 표지 한 줄로, 정리는 마무리로, 문제는 한 장에 모으라고 알려 준다). (2) 8장 이하이면 표지 부제가 있을 때 「학습 목표 장 없음」을, 마무리에 `sub`/`next`가 있을 때 「정리 장 없음」을, 활동 장이 없다는 알림을 내지 않는다. (3) 확인 문제 수는 `questions`까지 센다. (4) 그림 NOTE 두 가지를 더했다: 선으로 이어지지 않은 맨 도형 3개 이상(「실제 물건이라면 알아보게」), 그림 이름표를 옆 칸이 되풀이함 |
| `deck.py` · `deck_pptx.small_text()` | 저학년 `.pptx`에서 한 장 글의 40 % 이상이 22pt 미만이면 `WARN pptx: 저학년 글씨`를 낸다(위쪽 띠와 배지 글자는 세지 않는다). 막지는 않는다 |
| `deck_layouts.py` | 웹 비교 장에서 색 이름 알약(「위험해요」 빨강)이 대비 4.31로 FAIL이던 것을 고쳤다. 4.5가 될 때까지 색을 조금씩 짙게 한다(지난 측정 이후 그대로 남아 있던 버그) |
| `SKILL.md` · `references/content-slides.md` | 기준을 몇 줄 더했다: 실제 물건 그림은 알아보게(제 모양·색·테두리·안의 그림), 그림 옆 칸은 그림이 못 보여 주는 것을, 짧은 PPT는 틀을 줄이고 내용은 줄이지 않기, 「짧은 것은 문장이지 수업이 아니다」, 저학년은 24pt를 목표로. 「3 items or fewer per slide」는 뺐다 |
| `shared/content/CONTENT-RULES.md` | 「Floor, not ceiling」에 두 줄을 더했다: 실제 물건 그림은 알아보게 그리기, 짧은 결과물에서는 틀이 먼저 줄어든다. `sync_shared.py`로 스킬 7곳과 `dist/`에 복사 |

해 보고 되돌린 것: 저학년 글자 바닥을 20pt로 올리는 안. 지난 실행의 설명서 4개 가운데 2개에서 카드 머리(「노란불」)가 상자를 넘쳐 FAIL이 났다. 배치를 새로 짜지 않으면 멀쩡한 실행을 망가뜨리므로, 막는 대신 WARN으로 알리는 쪽을 택했다.

## 3. 다시 잰 결과

두 번 고쳤다. **고침 1**은 아이콘, 문제 묶음, 틀 줄이기, 그림 NOTE다. **고침 2**는 고침 1에 저학년 글씨 WARN과 「표지 부제는 짧게」를 더했다. 고침 2에서는 Claude 스튜디오 4개만 다시 만들었고, 같은 일반 파일과 함께 처음부터 다시 심사했다.

### 새 기능이 실제로 쓰였나 (스튜디오 Claude 8개: 고침 1 4개 + 고침 2 4개)

|---|---|

| 그림에 `icon` | 고침 2에서 4개 중 3개(5 · 3 · 9개). 고침 1에서는 원래 주제 1회차가 1개였다 |
| 저학년 글씨 WARN이 남은 채로 끝남 | 고침 2에서 4개 중 2개(원래 주제 1회차 3장, 새 주제 1회차 4장). 심사 노트의 「글씨가 작다」도 이 둘에 몰렸다 |

일반 Claude도 정지 표지를 빨간 네모로 그려 4개 모두 지적받았다. 표지판 모양을 모델이 정확히 아는지는 하네스가 보장하지 못한다.

## 6. 한계와 확인하지 못한 것

- **아직 지는 칸이다.** 두 주제 모두 -0.25다. 실행 2회, 심사 2회씩이고 같은 파일의 점수도 0.25까지 흔들린다. 그래서 「비김」과 「조금 짐」을 가를 수 없다. 이길 때까지 고치지 못했다.
- **글씨 WARN은 알림일 뿐이다.** 두 실행이 WARN을 남긴 채 끝냈다. 막도록(FAIL) 바꾸면 배치를 다시 짜야 하는 실행이 생긴다. 20pt 바닥을 시험했을 때 그랬다. 이번에는 하지 않았다.
- **한 장에 문제 여러 개(`questions`)의 보기 글씨가 작다**(22~24pt에서 시작해 줄어든다). 심사 노트에 「퀴즈 보기 글씨가 작다」가 남았다. 이 배치가 읽기 쉬움 점수를 깎았을 수 있다.
- **아이콘은 모양만 준다.** 뜻이 맞는 아이콘을 고르는지(달리기 금지 ≠ 발자국)는 모델 몫이고, 점검하지 않는다. 우리나라 표지판의 정확한 모양(정지 = 빨간 역삼각형)도 하네스가 알려 주지 않는다. 법령 그림은 저장소에 넣지 않았다.
- **GPT**: 새 스킬로 만든 것은 원래 주제 1회 하나다. GPT는 지난 측정처럼 조립 도구 대신 직접 PPT를 만들었을 수 있다(이번에는 설명서 파일이 남지 않았다).
- **새 NOTE의 오경보**: 「맨 도형」 NOTE는 선이 없는 도형 3개 이상이면 울린다. 수학의 도형 수업에서도 울릴 수 있다(문구는 「실제 물건을 나타낸다면」). 「같은 말 반복」은 낱말이 그대로 겹칠 때만 잡는다(「빨강: 멈춤」 ↔ 「빨간불: 멈춰요」는 놓친다).
