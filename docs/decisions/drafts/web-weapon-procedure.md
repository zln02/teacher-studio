# 초안 — 「웹페이지 무기」 절차 (매뉴얼·안내서형 사이트를 앱처럼 다듬기)

> 출처: noan-ai(노안중 AI교육 사이트) 다듬기 작업, 2026-11. 이 문서는 초안이며 아직 무기로 확정되지 않았다.
> 대상: 빌드 도구 없는 정적 사이트(HTML/CSS/JS), 선생님이 폰으로 보는 안내서·매뉴얼형 사이트.

## 0. 먼저 지킬 것 (사이트의 원칙을 읽는다)
README 를 먼저 읽고 **깨면 안 되는 선**을 적어 둔다: 외부 요청 0건 · 빌드 없음 · 데이터는 JSON(+file:// 폴백 JS) · 개인정보 경계 · 옛 주소 유지. 이후 모든 단계는 이 선 안에서만 한다.

## 1. 진단 (Diagnose) — 눈으로 보지 말고 재라
- 로컬 서버(`python -m http.server`)와 `file://` 둘 다 연다. 폰(390×844)·PC(1440×900) 전 페이지 스크린샷.
- 자동 측정 한 벌(Playwright, 시스템 크롬): 콘솔 오류 · 실패 요청 · **외부 요청(같은 출처 아니면 위반)** · 가로 넘침 · 손가락 크기(<40px) · axe-core(색 대비·이름표·헤딩 순서) · 이미지 alt.
- 기능 점검은 사람처럼: 검색창에 쳐 보고, 카드를 눌러 보고, 복사 버튼을 눌러 본다. 「JS가 안 도는 느낌」은 대개 **숨은 상자·잘못 연결된 이벤트**에서 나온다.
- 결과를 `docs/ux/diagnosis.md` + `before/` 스크린샷으로 남긴다. 좋은 점(유지할 것)도 적는다.
- 함정: axe 파일 경로 오타로 「위반 0」이 나올 수 있다 → 일부러 위반을 심어 측정기를 먼저 검증한다. `file://` 에서 axe 는 CSS 를 XHR 로 읽어 가짜 오류를 낸다 → axe 는 http 에서만.

## 2. 고객 여정 지도 (Journey)
사람 3유형 × 시간 3순간(전·중·후). 각 칸: 목표 · 행동 · 고민 · 기회. 이 사이트의 **한 줄 흐름**을 정한다 (예: 업무 찾기 → 카드 → 누를 곳 → 지시서 복사 → 주의). 홈 첫 화면에 무엇을 둘지는 여기서 나온다. 산출: `journey.md` + 외부 요청 없는 `journey.html`.

## 3. 정보 구조 (IA)
사이트맵 · 내비(폰 탭바 5개 / PC 위 메뉴) · **카드 해부** · 상세 템플릿(순서가 곧 여정) · 페이지 템플릿 · 새 슬롯(내용은 나중, 스키마와 자리만). 데이터 스키마는 JSON 에 `meta.schema` 로 적고, 없는 정보는 지어내지 않고 `null`+「확인 전」으로 보여 준다. 선택 기능(예: 피드백)이 있으면 어디까지가 정적 핵심이고 어디부터 선택인지 표로 가른다.

## 4. 카드 시스템 (Card system)
- 토큰 한 벌: 8px 격자 · 타입 스케일(13/15/17/20/24/30/40) · 색은 강조색 1개 + 의미색(성공·주의) · 반경 3단.
- 카드 해부를 한 컴포넌트로: 번호·분류·배지 / 제목 / 한 줄 / 칩(도구·시간) / 열기. 파스텔 무지개 대신 흰 카드+가는 테두리.
- 핵심 1급 컴포넌트(여기선 **지시서 상자**): 큰 복사 버튼 · 바꿀 곳 하이라이트 · 복사 직후 다음 행동 한 줄 · `file://` 에서도 복사(execCommand 폴백).
- 목록은 숨기지 않는다(「전체 보기」 접기 제거). 분류 칩 + 즉시 검색(공백 AND, 제목·한줄·도구·키워드).

## 5. 모바일/앱 다듬기 (Mobile / app polish)
- **덮어쓰는 층 하나**(`shared/app.css`)를 기존 CSS 맨 뒤에 읽게 하고, 옛 CSS 를 지우지 않는다(위험 최소). 우선순위 싸움은 `#id` 스코프로 푼다.
- 머리글은 폰에서 로고+주 버튼만, 메뉴는 **아래 탭바**(`shared/app.js` 의 배열 한 곳). 탭바 높이·안전영역 패딩.
- 한국어: `word-break: keep-all` 본문 전체 · `text-wrap: balance/pretty`. 손가락 44px. 포커스 링 3px. `prefers-reduced-motion`.
- 색 대비: 옛 토큰 hex 를 일괄 치환(예: #8494a8 → #5b6b7e).
- PWA: manifest(앱 이름·아이콘 192/512/maskable·standalone) + **루트 서비스 워커**(핵심 파일 precache, 나머지는 본 만큼 runtime, 오프라인 폴백 페이지). 목록은 파일 하나에, 바꾸면 버전 숫자 올리기. https/localhost 에서만 등록.
- `file://` 오류 정리: 시작부에서 `.json` fetch 를 조용히 거절해 data/*.js 폴백으로 넘긴다.
- 선택 기능(Supabase 등): 설정 파일이 비면 꺼짐 · anon 키만 · RLS insert-only · 막히면 한 줄 안내.

## 6. 외부 요청 0건 검사 (Zero-external check)
측정 스크립트가 모든 요청을 기록하고 **같은 출처/data:/blob:/file: 이 아니면 실패**로 센다. 서비스 워커 확인은 별도: 한 번 열고 → 오프라인으로 바꾸고 → 홈·상세·새 슬롯이 열리는지, 방문 안 한 주소는 폴백 페이지가 뜨는지.

## 7. 전후 비교 (Before / After)
같은 스크립트를 `before/`(원본 커밋을 worktree 로 열어서) 와 `after/` 에 돌리고, 폰 너비 5화면을 위(전)·아래(후)로 붙인 `before-after.png`(팔레트 PNG, ≤1.5MB). 수치표: 오류·외부 요청·axe 심각·손가락 크기.

## 8. 커밋
작은 단위: 진단 / 여정·IA 문서 / 앱 껍데기(css·js) / 홈 / 서비스 워커 / 새 슬롯 / 접근성 / 검증 산출물. push 는 소유자가 한다.

## 재사용 도구 (noan-ai 저장소 `tools/`)
`ux-audit.py`(전 페이지 측정) · `ux-axe-detail.py`(위반 요소 상세) · `ux-offline-check.py`(오프라인) · `ux-contact.py`(전후 시트) · `gen-pages.py`(뼈대 페이지).

## 열린 문제 (무기로 만들기 전에)
- 진짜 폰(iOS Safari 홈 화면 추가) 검증 절차가 없다.
- 옛 CSS 위에 덮어쓰는 방식은 빨리 되지만 CSS 가 쌓인다. 새 사이트는 처음부터 토큰+컴포넌트로 시작하는 템플릿이 필요하다.
- 3D/모션 장면(오프라인 HTML) 삽입 규약(샌드박스 iframe, 약한 PC 2D 폴백)은 아직 자리만 있다.
