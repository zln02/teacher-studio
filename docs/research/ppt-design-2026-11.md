## 1. 무엇을 바꿨나

모두 `skills/teacher-slides`의 PPT 내보내기다. 정해 둔 틀을 늘린 것이 아니라, 내용과 seed를 보고 고르게 했다. 사용자의 템플릿(`--template`)과 색(`palette_from`)이 먼저라는 규칙은 그대로다.

| 심사위원이 적은 말 | 바꾼 것 |
|---|---|
| 「장마다 비슷한 카드 배치」 | **장 종류마다 배치가 2~3가지.** 목록(줄 / 타일 / 왼쪽 색 면 + 목록), 단계(번호 줄 / 화살표 블록 / 사다리), 표지(색 블록 / 띠 / 단순), 비교(카드 / 마주 보는 면), 「항목 \| 내용」 표(이름표 타일), 연표·숫자·마무리·구분 장·한 문장 장. 그 장의 글이 읽을 만한 크기로 들어가는 배치만 후보가 되고, seed가 시작점을 정하며, 같은 배치를 두 번 잇지 않는다. `"layout": "bullets.grid"`로 정할 수도 있다. |
| 「한 가지 색이라 단조롭다」 | **주색 + 표시 색 둘까지.** 보조색과, 둘 다에서 색상이 먼 셋째 색(OKLCH로 계산)을 번호 원·카드 머리·그래프 계열에 쓴다. **주제에 제 색이 있으면 그 색**(화산은 붉은 주황, 바다는 파랑: 제목·교과 낱말에서 읽음). 기관 보고는 기존 남색 계열을 지키고 차분한 둘째 색 하나만 받는다. 형광색은 없다(`system.is_neon` 시험). |
| 「아이콘이 없다」 | **뜻으로 고르는 아이콘** (`scripts/deck_icons.py`). 줄이 무언가를 가리키면(전화, 지도, 달력, 화산 …) 그 Lucide 아이콘을 PPT에 **편집할 수 있는 윤곽선 도형 하나**로 그린다(그림 파일 아님, 색 바꾸기 가능). 웹 슬라이드도 같은 고르는 함수를 쓴다. 목록은 모든 줄에 제 그림이 있을 때만 아이콘을 쓰고 아니면 번호다. 한 글자 낱말은 따로 선 낱말일 때만 맞춘다(「생산」의 산은 산이 아님). |
| 「표·이름표·주석 글자가 작다」 | **14pt 아래로 내려가지 않는다**(어린 학년·어르신은 16pt). 표는 16pt부터, panel 안 이름표·주석·그래프 축 제목을 올렸다. 그보다 줄여야 들어가는 글은 「글이 길다」로 알린다. 점검기는 11pt 미만 FAIL, 14pt 미만 알림(전에는 10 / 12). |
| 「홍보 표지 색 면이 비어 있다」 | 색 면에 **주제 아이콘 + 읽는 사람이 움직일 사실 세 가지까지**(`hero.facts`: 날짜·장소·비용). |
| 「어린 학년 수업인데 어른스럽다」 | spec의 `audience`에서 **유치원~초3 / 초4~6 / 어르신**을 읽는다. 밝은 바탕만, 더 큰 글자, 더 둥근 도형, 표지에 주제 아이콘이나 그림, 모서리의 부드러운 원. 어두운 칠판·테크 모양은 이 청중에게 안 나온다. |

그 밖에: 근사 미리보기가 윤곽선 도형(채우지 않는 경로, 둥근 끝)을 그대로 그리게 했다. 일반 AI 덱에는 영향이 없다.

**아이콘 라이선스.** 새로 받은 것은 없다. 이미 들어 있던 Lucide 1.75.0(`shared/vendor/lucide/`)을 PPT에도 쓴다. LICENSE 파일을 다시 읽었다: ISC, Feather에서 온 아이콘은 MIT. `shared/vendor/manifest.json`과 `NOTICE`에 PPT에서 쓰는 방식을 적었다.

## 2. 숫자

방법은 지난번과 같다. 만드는 쪽 `claude -p --model sonnet`, 같은 요청 문장 + 「알아서 끝까지 만들어 줘. 결과 파일은 지금 폴더에 저장해 줘.」. 일반 AI = 로그인만 있는 설정(계정 기본 pptx 스킬 포함), 스튜디오 = 같은 설정 + `py scripts/setup.py --agent claude-code`로 설치된 스킬. 주제마다 2번, 수정 요청 없음. 같은 미리보기로 그린 그림을 Opus가 A/B 익명으로 심사(글자 배정 무작위, 글자를 바꿔 한 번 더). 「평균」은 실행 2번 x 심사 2번 x 4항목, 「최악」은 실행별 평균 가운데 낮은 쪽.

## 3. 아직 지는 곳

1. **초등 저학년 (3.88 대 4.38).** 가장 뚜렷한 패배다. 글자와 도형은 키웠지만 심사위원은 「차분한 색」「템플릿 느낌」「카드 안이 비어 보임」「정답 장 글씨가 작음」이라고 적었다. 일반 AI는 낱말마다 그림(이모지)을 붙이고 원색을 쓴다. 스튜디오는 이모지를 지우고(규칙), 낱말 카드에 그림이 붙지 않으며, 주제에서 고른 색이 한 톤으로 차분하다. 다음에 볼 것: 저학년 덱에서 낱말·예시마다 그림을 붙이는 블록, 저학년용 더 밝은 색 조합, 정답 장을 한 문제일 때 크게.
2. **가장 못 나온 한 번 (3.38 대 3.50).** 방과후학교 보고의 두 번째 실행이 예산 집행을 빼고 숫자를 적게 넣었다. 같은 주제 첫 번째 실행은 4.62였다. 디자인이 아니라 「기관 보고는 무엇을 꼭 담아야 하나」가 실행마다 흔들리는 문제다.
3. **홍보의 디자인 항목 (4.0 대 4.5~4.75).** 색 면에 아이콘과 사실을 넣었는데도 일반 AI의 표지·카드가 더 화려하다는 평이다. 전체 점수는 이겼다.
4. 기관 보고에서 「우리 학교」를 자리표시로 본 심사가 있었다(모르는 기관명은 이렇게 쓰라는 것이 지금 규칙).
5. 화면이 성긴 장(짧은 글 3개가 든 큰 카드, 한 문제뿐인 정답 장)에서 「비어 보인다」는 평이 남았다.

## 4. 확인하지 못한 것 (그대로 믿으면 안 되는 부분)

- **실제 PowerPoint로 열어 보지 않았다.** 이 PC에는 PowerPoint도 LibreOffice도 없다. 모든 그림은 pptx 파일을 읽어 그린 근사 미리보기다. **아이콘은 직접 만든 도형 데이터(custGeom)라서 실제 PowerPoint에서 어떻게 보이는지가 이번에 가장 확인이 필요한 부분이다.** python-pptx로 다시 읽히는 것, 미리보기에서 제대로 그려지는 것, 2,403개 아이콘이 모두 변환되는 것까지만 확인했다.
- 주제 7개, 주제마다 실행 2번, 심사 2번이다. 0.25점 안팎의 차이는 흔들림 안이다(주제별 +0.06, 0.00은 「같다」로 읽어야 한다). 맞대결도 같은 쌍을 두 번 본 것이라 독립된 28번이 아니다.
- 다시 돌린 3개는 지난번 결과물과 심사 노트를 보고 고친 주제다(주제 이름을 규칙에 넣지는 않았지만, 주제의 색을 고르는 낱말 표에 「화산」「스마트폰」「경제」 같은 흔한 낱말이 들어 있다). **새 주제 4개가 그 영향을 받지 않은 값이다.**
- 일반 AI의 다시 돌린 3개 덱은 지난번 파일이다. 새로 만들면 달라질 수 있다.
- 심사위원은 한 모델(Opus)이고 그림만 봤다. 만드는 쪽은 Sonnet 하나다.
- 웹 슬라이드는 같은 색·같은 아이콘 고르기를 쓰게 됐지만, 새 배치·`hero.facts`·더 큰 글자는 PPT 쪽에만 넣었다. 웹 슬라이드는 시험 통과만 확인했고 눈으로 심사하지 않았다.
- 템플릿을 준 경우는 단위 시험만 했다(템플릿의 마스터 유지, 큰 색 면을 얹지 않음, 사용자 색에 우리가 만든 색을 더하지 않음). 실제 사용자 템플릿으로 심사하지 않았다.
- 심사 전에 평가 밖 주제(초3 자석의 이용)로 한 번 시험 삼아 돌렸고, 그 결과를 보고 모서리 장식 점의 위치 하나를 옮겼다. 평가에 쓴 14번은 그 뒤의 코드다.
