# 디자인 점검표 (만든 뒤 보여 주기 전에 반드시)

순서: **만들기 → 점검(check) → 디자인 점검(`design_review.py`) → 위 PNG(접촉 시트)를 직접 눈으로 보기 → 이 표대로 고치기 → 다시 만들기 (최대 2번)**

```
python3 scripts/design_review.py game.html --out review/
```
`review/<이름>-sheet.png`(제목·문제·정답·오답·결과·배경만 6칸)를 **그림으로 열어서** 아래를 하나씩 확인해요. 숫자(`-metrics.json`)는 보조예요. 눈으로 본 판단이 우선이에요.

## 눈으로 보는 8가지 (아니오가 하나라도 있으면 고친다)
| 질문 | 아니오일 때 고치는 법 (spec) |
|---|---|
| 1. **장면이 있나요?** (그냥 색 바탕이 아니라 우주·바다·무대처럼 어디인지 보이나요) | `design.words`에 장면 낱말 넣기 (우주·바다·숲·무대·역사 …) |
| 2. **시선이 한 곳으로 모이나요?** (제일 먼저 문제/제목이 보이나요, 장식이 글자보다 튀지 않나요) | 문제 글 줄이기, 장식이 센 테마 대신 차분한 `mood` |
| 3. **휑하지 않나요?** (빈 면이 넓지 않고, 가장자리·바닥에 장식이 있나요) | `theme:auto` + 소품이 많은 분위기 낱말, `seed` 바꾸기 |
| 4. **도우미 캐릭터와 소품이 주제와 맞나요?** (역사 게임에 로봇이 나오면 어색해요) | `design.words`에 주제 낱말(역사·우주·재활용 …)을 넣으면 맞는 캐릭터가 골라져요 |
| 5. **축하 연출이 있나요?** (정답·끝날 때 반짝임·꽃가루·박수 같은 것) | 결과 화면까지 놀아 보고, 없으면 `mood`를 신남/밝음으로 |
| 6. **글자가 잘 읽히나요?** (카드 안 글자, 제목, 버튼. 장식에 묻히지 않나요) | 대비 숫자 2 미만이면 필수 수정: `mood`를 차분하게 |
| 7. **서로 겹치는 것이 없나요?** (캐릭터·말풍선·글자 상자) | 보기 줄이기, 글 줄이기 |
| 8. **색이 어울리나요?** (색이 너무 적어 밋밋하거나, 반대로 너무 많아 어지럽지 않나요) | `mood`/`seed` 바꾸기 |

## 숫자 기준 (옛 스킨 9개를 같은 방법으로 잰 값과 비교, `assets/design-baseline.json`)
- `deco_density` 장식 밀도: 배경에 무늬·그림이 있는 칸의 비율. 옛 스킨 최저선보다 낮으면 WARN
- `empty_ratio` 휑함: 카드 밖에서 단색인 칸의 비율. 옛 스킨 최고선보다 높으면 WARN
- `colors` 색 가짓수: 옛 스킨 최저선보다 적으면 WARN
- `hierarchy` 가장 큰 글자 ÷ 보통 글자: 1.25 미만이면 시선이 흩어져요
- `min_contrast` 글자 대비: 2 미만 FAIL, 4.5 미만 WARN
- `overlaps` 겹침: 0이어야 해요
WARN이 나와도 눈으로 보아 괜찮고 이유가 있으면 그대로 두어도 돼요. FAIL은 고쳐요.

## 한 번 고칠 때의 순서
1. 가장 큰 문제 하나만 고른다 (보통 3·4번).
2. spec의 `design.words` / `mood` / `seed`만 바꾼다 (문제·정답은 그대로).
3. 다시 `build.py` → `design_review.py` → 그림 보기. 2번을 넘기면 지금 모양으로 보여 주고 「이 부분은 이렇게 했어요」라고 알린다.
