# 천장 평가: 일반 AI vs 교사 스튜디오, 8개 과제 x 4조건 (2026-11-20)

## 결론 먼저

- **두 성공 기준 모두 이번 실험에서는 "확실히 달성"이 아니다.** (a) sonnet+스튜디오가 fable 일반 AI 이상인 과제는 **4/8**(평균 점수차 +0.08), (b) fable+스튜디오가 fable 일반 AI보다 나은 과제는 **4/8**(평균 +0.22). 평균 차이는 심사 점수의 흔들림(1점 안팎)보다 작아서 "비겼다"가 정직한 표현이다.
- **스튜디오가 분명히 이긴 곳:** 한글(hwpx) 가정통신문(fable 4.25 대 2.88), 게임, 처음 보는 요청(역할 정하기, 두 모델 모두 +1.0). 일반 AI는 날짜·장소를 빈칸으로 두거나 「작성 안내」 문구를 남겼고, 스튜디오는 날짜·경비·요일을 채웠다. 점검기 실패도 fable 기준 8건 대 2건이다(점검기 중립 항목만 센 값).
- **일반 AI가 이긴 곳:** 수업 PPT, 공공 보고 PPT, PDF 안내문(+신청서). 세 곳 모두 sonnet 일반 AI 또는 fable 일반 AI가 위였다. 특히 **sonnet 일반 AI가 전체 평균 점수 1위(3.92)** 였고 sonnet 스튜디오(3.67)보다 높았다.
- **속도:** fable은 스튜디오가 첫 결과가 3배 빠르다(중앙값 168초 대 532초). fable 일반 AI는 PPT에서 1161~1340초(약 20분)가 걸린 경우가 2번 있었다. sonnet은 일반 AI가 더 빠르다(115초 대 180초).
- **비용:** 만들기 비용 합계 fable 일반 $24.5 / fable 스튜디오 $28.6 / sonnet 일반 $9.1 / sonnet 스튜디오 $7.7. 수정 요청(이어 말하기)이 들어가면 fable 쪽이 크게 늘었다.
- **한계(꼭 읽기):** PPT는 이 PC에 LibreOffice가 없어 파일 안 도형으로 **근사해 그린 그림**으로 심사했다. 그림·일부 도형이 빠져 "빈 슬라이드"로 보인 곳이 있고(수업 PPT 네 개 모두 「오목·볼록」 또는 「비교」 장), 이것이 조건별로 공평한지는 확인하지 못했다. 게임·프로그램은 시작 화면과 몇 번 눌러 본 정지 화면만 봤다. **실행 1회씩, 심사 2회 평균**이라 소수점 차이는 의미가 약하다.

## 일반 AI가 이긴 곳과 이유

- **수업 PPT / 공공 보고 PPT:** 심사 노트상 스튜디오 쪽 덱은 「본문이 비어 보이는 장」과 `(학교명 입력)` 자리가 많았다(sonnet 스튜디오 공공 PPT: 모든 장에 학교명 자리, `pptx_check` 실패). 일반 AI 덱도 `[교육지원청명을 넣어 주세요]`·`○○부` 같은 빈칸이 있었지만 구성과 색이 더 안정적으로 보였다는 평가. 그림이 근사 미리보기라 이 차이의 일부는 미리보기 한계일 수 있다.
- **PDF 안내문:** 일반 AI(특히 fable)가 일정표·1·2지망 체크 신청서까지 더 완성된 모양이었다. 스튜디오 쪽은 학교명이 `우리초등학교` 같은 임시 이름이거나 신청서에 학생 이름·서명 칸이 빠진 경우가 있었다(sonnet 스튜디오). fable 스튜디오는 같은 요청에 $8.32를 써서 일반 AI($4.77)보다 비쌌다.
- **수학 프로그램:** fable은 일반 AI가 근소하게 위(-0.25), sonnet은 스튜디오가 위(+0.75). 사실상 비김.
- 스튜디오가 항상 이기지 않는 이유(추정): 「알아서」로 질문을 건너뛰면 학교·날짜 같은 정보가 비어 있고, 스튜디오가 이를 `fillins`(바꿔 넣을 곳)로 표시해도 그림에는 빈칸으로 보인다. 일반 AI는 비슷한 빈칸을 더 자주 남겼지만 PPT에서는 점수가 갈렸다.

## 방법 (재현용)

- 설정: 일반 AI = 로그인 정보만 있는 새 `CLAUDE_CONFIG_DIR`(계정 기본 스킬만 있음), 스튜디오 = 같은 설정에 이 저장소 `skills/`의 8개 스킬. 실행 전 두 설정의 스킬 목록을 작은 호출로 확인(일반 AI에는 `teacher-*` 없음, 스튜디오에는 8개). 모델 `claude-fable-5-2`·`sonnet`, `claude -p --permission-mode bypassPermissions --output-format json`, 실행마다 빈 임시 폴더, 25분 상한. 동시에 2개까지, 브라우저는 한 번에 하나.
- 요청: 과제 문장 + 「 알아서 끝까지 만들어 줘. 결과 파일은 지금 폴더에 저장해 줘.」(이전 비교와 같은 저장 문구, 모든 조건 동일). PDF는 같은 대화에서 두 번째 요청 「이 PDF 끝에 신청서 페이지를 하나 붙여 줘」.
- 검수와 수정: 검수자(`claude -p --model opus`, 스킬 없는 새 설정)가 그림과 파일을 보고 고정 점검표 9개(열림·빈칸·잘림·가독성·형식·정확성·개인정보·오프라인·요청부합)로 최대 3개 수정 요청을 쓴다. 한 번의 수정 요청 묶음 = 1회로 세어 `claude -p --resume`로 같은 대화에 보내고 최대 3회. 「충분해요」면 멈춘다. 검수자 프롬프트에는 「학교명처럼 AI가 모르는 값을 밑줄 빈칸으로 두고 안내했다면 문제로 보지 마」라는 문장이 있다(예행에서 검수자가 앞뒤가 안 맞는 요구를 반복해 추가).
- 그림: PPT는 우리 근사 미리보기(`pptx_render.py`), hwpx는 우리 미리보기, PDF는 쪽 그림, HTML은 헤드리스 Chrome(시작 화면+버튼 3번). 익명화: 과제마다 A~D 무작위 배정, 심사 2회는 순서를 바꿈. 매핑은 `raw/judge/*.json`(심사자에게는 보이지 않음).
- 사고: 실행 중 `claude.exe`가 업데이트되어 일부 실행이 시작 전에 죽었고, 복사해 둔 로그인 정보가 만료되어 PDF 4건·게임 1건이 0초로 실패했다. 해당 결과는 버리고 전부 다시 돌렸다(최종 32개는 모두 정상 실행). 버린 예행(PDF sonnet 일반 AI, 검수 문구 수정 전)은 표에 넣지 않았다.
