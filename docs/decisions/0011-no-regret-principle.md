# 0011. 무손실 원칙: 하네스 때문에 맨 모델보다 나빠지면 안 된다

- 상태: Accepted (런타임 규칙은 구현, 평가 관문은 「계획」) (2026-11-19)

## 배경
소유자의 원칙: 「우리 하네스로 손해 보면 안 된다. 무조건 이득만 보도록, 손해 보는 곳들은 손해 안 보도록.」 즉 같은 요청에서 하네스를 쓴 결과가 **하네스 없는 맨 모델보다 나빠지는 경우가 없어야 한다**(no-regret). 지침·스크립트·미사일은 잘 맞으면 큰 이득이지만, 안 맞는 곳에 억지로 쓰면 토큰·시간·획일성·낡은 정보로 오히려 손해가 된다. 실제로 옛 스킨 기준에 디자인이 끌려가는 쏠림이 관찰되었다(편향 정리, CHANGELOG 참고).

## 결정
손해가 날 수 있는 지점마다 완화책을 둔다.
| 손해 위험 | 완화책 |
|---|---|
| 토큰 오버헤드 | 항상 읽는 입구를 작게(teacher-studio SKILL.md 본문 약 150줄 이하 목표, 실제 측정은 「계획」). description은 관련 요청에만 발동하고, 자세한 내용은 필요할 때만 읽고, 무거운 일은 스크립트가 한다 |
| 안 맞는 도구 억지 사용 | **확신 관문**: 요청이 분명히 맞을 때만 무기를 쓴다. 아니면 비켜서서 모델 자신의 지식과 환경 기본 도구로 하되, 법 안내·점검기·읽기 쉬운 결과 규칙은 그대로 적용 |
| 하네스 경로 실패·반복 | 고치기 최대 2번, 그래도 안 되면 맨 모델 방식으로 돌아가 한 줄로 알린다 |
| 쏠림·획일성 | 기본이 다양성. 옛 스킨 부품은 최하 우선순위, 닮음 검사(`design_review.py`) |
| 낡은 정보(도구·법·벤더 기능) | 실시간 조회 + 날짜가 적힌 목록, CI에서 만료 점검(「계획」) |
| 과한 제한 | 안전·학생 개인정보 외에는 알려 주기만 하고 막지 않는다 (ADR 0005·0006) |
| 숨은 비용(설치·시간) | 크기·시간을 보여 주고 동의를 받는다. 큰 것은 자동 설치하지 않는다 (`ensure.py`) |
| 선생님의 뜻과 충돌 | 「하네스 없이 해 줘」「그냥 네 방식대로」라고 하면 AI가 따른다 |
| 이득의 증거 부재 | **평가 관문(「계획」, 포트폴리오 단계)**: 같은 요청을 맨 모델 vs 하네스로 돌려 비교. 토큰을 더 쓰지 않고 품질이 앞설 때만 기본 켬, 아니면 「실험 기능」으로 표시하고 기본 끔 |

## 검토한 대안
- **무조건 하네스 경유**: 일관되지만 안 맞는 요청에서 손해. 기각.
- **하네스 없음**: 손해는 없으나 점검기·법 안내·상용 품질 설계가 사라짐. 기각.
- **사용자 설정 스위치만 제공**: 비개발자 교사에게 부담. 말로 하는 해제 문구로 대체.

## 결과
- 장점: 하네스는 이길 때만 개입하고, 질 때는 물러선다. 교사는 언제든 끌 수 있다.
- 단점: 확신 관문의 판단이 AI에 달려 있고, 평가 관문이 구현되기 전에는 「이득」이 측정이 아니라 설계 의도에 머문다.

## 근거/측정
- 런타임 규칙: `skills/teacher-studio/SKILL.md`의 「무손실 규칙(No-regret rules)」.
- 관련 기록: ADR 0004(점검기 관문), 0005·0006(안내만 / 학생 정보 금지), 0009(공식 스킬 재사용).
- 「계획」: SKILL.md 줄 수·토큰 실측, 맨 모델 대비 평가 관문, 만료 점검 CI.
