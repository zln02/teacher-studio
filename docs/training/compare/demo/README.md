# 라이브 시연 사전 테스트: 「AI 코딩 도우미 만들어줘」 일반 AI vs 교사 스튜디오 (2026-11-19)

## 결론 먼저

- **이 프롬프트로는 두 화면 시연이 약합니다. 눈에 띄는 차이가 거의 없습니다.** 둘 다 "미리 만든 규칙으로 답하는" 코딩 도우미 HTML 한 개를 냈고, 겉모습 수준도 비슷했습니다. 오히려 첫 화면은 일반 AI가 더 화사했습니다(보라색 머리띠, 말풍선 채팅).
- **교사 스튜디오 쪽은 하네스를 거의 쓰지 않았습니다.** 스킬을 읽거나 `studio.py`·점검 도구를 부른 기록이 없습니다. "물어보지 말고 알아서"라는 말을 받자 바로 서브 에이전트 1개에게 맡겨 HTML을 직접 쓰게 했습니다. 전용 미사일(게임·발표·보고서 같은)이 없는 요청이라 "스킬 스카우트 / 기본 길"로 넘어간 것으로 보이지만, 그 판단 과정은 기록에 남지 않았습니다. 공통 디자인 도구(`design.py`)와 `check` 점검도 돌린 흔적이 없습니다.
- 그 결과 **하네스 쪽이 시간 5.9배(85초 대 499초), 비용 3.5배($0.28 대 $0.99)** 인데 눈에 보이는 이득은 아래 정도입니다.
- **교실에서 깨질 만한 점은 일반 AI 쪽에 있습니다.** 파이썬 실행기를 인터넷(CDN)에서 내려받아서 학교 망이 막히면 "실행" 버튼이 안 됩니다. 채팅 답에 `**굵게**` 표시가 그대로 보이는 흠도 있습니다. 하네스 쪽은 외부 요청 0건, 인터넷 없이 동작합니다.
- 두 결과 모두 **진짜 AI가 아닙니다**(키워드별 미리 써 둔 답). API 키는 필요 없고 비용도 없지만, "AI 코딩 도우미"라는 이름에서 기대하는 자유 질문 답변은 못 합니다. 이건 두 쪽이 같은 한계이고, 둘 다 최종 답변에서 솔직히 밝혔습니다.

## 비교표 (점수는 제가 직접 본 주관 점수, 단일 실행)

|---|---|---|
| 작동 | 예 (파이썬 실행됨, 질문 답 나옴, 오류 없음) | 예 (JS 실행됨, 질문 답 나옴, 오류 없음) |
| 디자인 (1~5) | 4 (보라 머리띠, 채팅 말풍선, 깔끔) | 3 (카드형이지만 "질문" 버튼 글자가 세로로 꺾임, 화면이 세로로 길어 아래로 스크롤) |
| 내용 정확성 (1~5) | 4 (반복문 설명 맞음) | 4 (반복문 설명 맞음) |

- 언어도 다릅니다. 일반 AI는 파이썬(수업 현장에 더 익숙), 하네스는 자바스크립트(브라우저에서 바로 돌아 인터넷이 필요 없음). 둘 중 어느 쪽이 맞는지는 수업에 따라 다릅니다.
- 하네스 쪽이 더 많이 넣은 것: 예제 11개, 미션 6개(자동 채점), 힌트 단계, 글자 크기·다크 모드(빔프로젝터 배려), 무한 반복 3초 차단.
- 하네스 쪽은 만든 뒤 Node로 문법·예제를 점검했다고 보고했습니다. 일반 AI는 "열어서 실행해 보지는 못했다"고 했습니다. 다만 이 점검도 하네스 도구가 아니라 서브 에이전트가 스스로 한 것입니다.

## 시연에 쓸 수 있나

- **그대로는 권하지 않습니다.** 화면 두 개를 나란히 놓으면 "비슷한데 한쪽이 6배 느리고 3배 비싸다"가 먼저 보입니다. 청중이 볼 차이는 "인터넷 없이 되는가", "글자 크기 조절", "미션 채점" 정도인데, 첫 화면에서는 안 보입니다.
- **더 분명하게 만들려면**
  - 하네스가 전용 미사일을 가진 요청으로 바꿉니다. 예: 「코딩 수업 복습 퀴즈 게임 만들어 줘」(teacher-game), 「코딩 수업 발표자료 만들어 줘」(teacher-slides). 이 경우 지난 비교(v2)처럼 무대·점검·디자인이 실제로 적용됩니다.
  - 꼭 코딩 도우미를 쓰고 싶다면 "알아서 만들어" 대신 하네스가 자기 길(환경 확인, 디자인 정하기, 점검)을 타도록 두는 편이 낫습니다. 이번에는 "물어보지 말고"가 그 길을 건너뛰게 만든 것으로 보입니다(추정이며, 확인하려면 같은 프롬프트에서 그 문구만 뺀 실행이 필요합니다).
  - 시연 중간에 "학교 인터넷 끊김"을 일부러 보여 주면 일반 AI 쪽 파이썬 실행기가 멈추는 장면을 만들 수 있습니다. 다만 그건 하네스의 장점이라기보다 이번 일반 AI 결과의 우연한 약점입니다.
- 매번 결과가 달라서, 같은 프롬프트로 다시 돌리면 일반 AI가 CDN 없이 만들 수도 있습니다.

## 하네스가 이 요청을 어떻게 다뤘나

- 기록(세션 로그)에서 확인한 것: 메인 세션의 도구 호출은 `Agent`(general-purpose, sonnet) 1번뿐이었습니다. `Skill` 호출, `studio.py`, `check`, `design.py`가 없었습니다. 서브 에이전트가 HTML을 `Write`로 한 번에 쓰고, Node 스크립트로 자체 점검했습니다.
- 즉 "전용 미사일 없음 → 스킬 스카우트/기본 길 → 디자인·점검 적용" 흐름은 이번에는 **타지 않았습니다.** 하네스 스킬이 설치돼 있어도 매번 쓰는 것이 아니고, 요청 문구에 따라 건너뛸 수 있다는 뜻입니다.
- 디자인 규칙(ES2017, 외부 이미지 금지, 학생 정보 칸 금지)은 결과에 우연히 지켜졌습니다(`?.`·외부 요청 없음). 규칙이 적용돼서인지는 알 수 없습니다.

## 방법

- 지난 비교(`../README.md`)와 같은 방법입니다. `CLAUDE_CONFIG_DIR`을 로그인 정보만 있는 폴더(일반 AI)와, 그 위에 `~/.claude/skills`의 `teacher-*` 7개를 복사한 폴더(하네스)로 지정해 `claude -p --model sonnet --permission-mode bypassPermissions --output-format json`으로 실행했습니다. 각자 빈 임시 폴더, 동시에 실행, 제한 시간 20분. 먼저 작은 호출로 두 설정 모두 작동을 확인했습니다.
- 요청 문장은 아래 그대로이고, 지난 비교와 달리 "알아서 끝까지"·저장 문구를 덧붙이지 않았습니다. 문장에 이미 "알아서 만들어"가 들어 있습니다.
  - 「나는 중학교 선생님인데 오늘 수업에 쓸 프로그램을 만들어야 하는데 코딩수업에 쓸 AI 코딩 도우미 만들어줘! 나한테 물어보지말고 너가 알아서 만들어」
- 확인: Playwright chromium(`--mute-audio`) 1600x900. 시작 화면, 기본 코드 실행, 질문 입력("반복문이 뭐예요?") 순으로 눌러 봤고 네트워크 요청과 콘솔 오류를 기록했습니다(`raw/shot.py` 참고).
- 파일: `bare.png`, `harness.png`(질문 후 화면), `side-by-side.png`, 첫 화면 `bare-first.png`·`harness-first.png`, 결과 HTML과 `_result.json`·`_secs.txt`는 `raw/`.
- 한계: 한 번씩만 실행했습니다. 하네스 쪽 점수·판단은 단일 실행이고, 비용에 서브 에이전트 몫이 들어갔는지 모릅니다. 일반 AI의 이름 입력("안녕, "만 나옴)은 자동 클릭 환경에서 입력창을 채우지 않아서일 수 있어 결함으로 단정하지 않습니다.
