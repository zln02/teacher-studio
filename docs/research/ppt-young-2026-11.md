## 한눈에 (쉬운 말로)

- **지난번에 졌던 초등 저학년 수업에서 이번에는 앞섰다. 새 저학년 주제 3개 평균이 일반 AI 3.69, 스튜디오 4.21 (1~5점).** 지난번 저학년 주제(흉내 내는 말)는 4.38 대 3.88로 졌다. 주제가 다르므로 같은 자로 잰 전후 비교는 아니다.
- 저학년 3개 가운데 **2개는 뚜렷이 이겼고(1학년 여러 가지 모양 +0.62, 3학년 동물의 한살이 +0.88), 1개는 같다(2학년 안전하게 길 건너기 +0.06, 맞대결 2 대 2).**
- 저학년 디자인 점수는 3.58 대 **4.42**다. 지난번 저학년 주제에서는 4.50 대 4.00으로 졌던 항목이다.
- **기관 보고(학교 도서관 운영 결과)는 두 번 모두 4.50이고 예산 집행 표가 두 번 다 들어갔다.** 지난번 가장 못 나온 한 번(3.38)은 예산을 빼서 생겼다. 일반 AI는 3.06이다.
- 5개 주제 전체: 일반 AI 3.55, 스튜디오 **4.25**. 가장 못 나온 한 번도 스튜디오가 높다(2.62 대 **3.50**). 나란히 놓고 물은 20번 가운데 스튜디오 17번, 일반 AI 3번.
- 지난번에 이긴 주제(중1 고려의 건국)는 다시 만들어도 이겼다(+0.50, 3 대 1). 지난번 +0.81보다는 작다.
- **아직 남은 약점: 스튜디오의 가장 낮은 한 번(3.50)은 저학년 수업이다.** 「초록불」 칸 머리가 주황색, 「빨간불」 칸 머리가 보라색으로 칠해졌고(색은 순서대로 돌려 쓰는데 내용의 색과 어긋남), 표지 그림이 비어 보였고, 정리 장이 문제와 정답 사이에 끼었다.

## 1. 무엇을 바꿨나

모두 `skills/teacher-slides`다. 사용자의 템플릿(`--template`)과 색(`palette_from`)이 먼저라는 규칙은 그대로이고, 시험으로 확인했다.

| 지난번 심사위원이 적은 말 | 바꾼 것 |
|---|---|
| 「색이 차분하고 어른 취향」 | **유치원~초3은 크레파스 같은 세 가지 색.** 주제에 제 색이 있으면 그 색에서, 없으면 seed로 고른 색에서 시작해 색상환의 3분의 1씩 떨어진 두 색을 더한다. 밝고 진하지만 형광색은 아니다(`system.is_neon` 시험을 주제 7개 x seed 12개에서 통과). 노랑이 주색이면 흰 글자가 안 읽혀서 귤색으로 바꾸고 노랑은 표시 색으로 남긴다. |
| 「낱말에 그림이 없다」(일반 AI는 이모지) | **낱말 앞의 이모지 하나가 그 낱말의 그림이 된다.** 「🐶 멍멍: 강아지가 짖어요」라고 쓰면 빌드가 이모지를 글에서 떼어 내 낱말 옆에 크게 그린다(그림 타일, 그림 줄, 퀴즈 보기, 비교 칸, 단계, 표지 `"pic"`). 제목과 문장에는 이모지가 남지 않는다. 다른 청중의 덱은 전처럼 이모지를 지운다. 이모지 대신 낱말을 주면 전처럼 Lucide 아이콘을 고른다. |
| 「템플릿 느낌」「카드 안이 비어 보임」 | 저학년 덱의 목록 카드가 **저마다 제 색으로 옅게 칠해진다.** 그림이 있는 목록은 그림 타일이 먼저 나오고, 바로 앞 장이 타일이면 줄 모양으로 바뀐다. 표지 3가지·목록 여러 가지 배치가 seed로 도는 것은 그대로다. |
| 「정답 장 글씨가 작다」 | **정답 장을 문제 수에 맞춰 키웠다.** 한 문제면 문제 28~30pt, 정답은 색 띠에 38pt, 풀이 26~28pt. 두 문제면 24 / 28pt(전에는 22 / 26pt). 표지의 부제·안내 줄과 장 위 이름표도 어린 학년·어르신 덱에서 키웠다. |
| (기관 보고) 「예산 집행 내용이 없다」 | **꼭 담을 내용 점검.** 요청 문장(`"request"`)과 제목이 이름 붙인 것(예산, 성과, 계획 …)과, 결과 보고라면 읽는 사람이 찾는 네 가지(실적, 예산, 성과, 계획)를 본문 장이 다루는지 본다. 빠지면 `꼭 담을 내용이 빠졌어요: 「예산」`이라고 알린다. 요약 장에 한 줄 스친 것은 다룬 것으로 치지 않는다. 정말 해당 없으면 `"omit"`으로 알린다. 수치가 든 장이 너무 적어도 알린다. |

저학년 덱에 낱말 그림이 절반도 안 붙었거나 표지에 그림이 없으면 빌드가 알려 준다. `SKILL.md`의 내용 요리법에도 두 줄(저학년 그림, 보고서 요청 문장)을 넣었다.

## 2. 숫자

방법은 지난번과 같다. 만드는 쪽 `claude -p --model sonnet`, 같은 요청 문장 + 「알아서 끝까지 만들어 줘. 결과 파일은 지금 폴더에 저장해 줘.」. 일반 AI = 로그인만 있는 설정, 스튜디오 = 같은 설정 + 설치된 스킬. 주제마다 2번, 수정 요청 없음. 같은 미리보기로 그린 그림을 Opus가 A/B 익명으로 심사(글자 배정 무작위, 글자를 바꿔 한 번 더). 「평균」은 실행 2번 x 심사 2번 x 4항목, 「최악」은 실행별 평균 가운데 낮은 쪽.

새 주제 4개는 어떤 평가·시험·예시에도 쓴 적이 없고, 돌리기 전에 정했다. 다시 돌린 1개는 지난번에 가장 크게 이긴 주제이고, 일반 AI 덱은 지난번 파일 그대로(심사는 새로 했다), 스튜디오만 새로 만들었다.

| 주제 | 일반 AI 평균 / 최악 | 스튜디오 평균 / 최악 | 차이 | 맞대결 (스튜디오-일반 AI) |
|---|---|---|---|---|
| (새) 초1 수학 여러 가지 모양 | 3.50 / 3.12 | 4.12 / 3.88 | +0.62 | 4-0 |
| (새) 초3 과학 동물의 한살이 | 3.69 / 3.62 | 4.56 / 4.50 | +0.88 | 4-0 |
| (새) 초2 안전한 생활 안전하게 길 건너기 | 3.88 / 3.75 | 3.94 / **3.50** | +0.06 | 2-2 |
| **저학년 3개** | **3.69 / 3.12** | **4.21 / 3.50** | **+0.52** | **10-2** |
| (새) 교육지원청 보고 학교 도서관 운영 결과 | 3.06 / 2.62 | 4.50 / 4.50 | +1.44 | 4-0 |
| **새 주제 4개** | **3.53 / 2.62** | **4.28 / 3.50** | **+0.75** | **14-2** |

| **5개 전체** | **3.55 / 2.62** | **4.25 / 3.50** | **+0.70** | **17-3** |

## 3. 아직 약한 곳

1. **색이 내용의 뜻과 어긋날 수 있다.** 비교 장의 두 칸 머리는 덱의 색을 순서대로 쓴다. 「초록불 / 빨간불」처럼 낱말 자체가 색인 경우에도 그래서, 초록불이 주황, 빨간불이 보라로 나왔다. 저학년에게는 헷갈리는 표현이다. 고치지 않았다.
2. **표지의 직접 그린 그림(`shapes`)이 허전하다.** 만드는 쪽이 `pic` 대신 도형 몇 개로 도로를 그린 실행에서 「표지 그림이 거의 비어 있다」는 평을 받았다.
3. **정리 장이 문제와 정답 장 사이에 낀다.** 「확인 문제 정답」 장은 마무리 장 바로 앞에 들어가는데, 마무리 장 없이 정리로 끝나는 덱에서는 순서가 어색해진다.
4. **요청보다 장이 조금 많다.** 저학년 「8장 정도」에 9장(두 주제 모두), 「10장 정도」에 12장이 나왔다. 빌드가 허용하는 범위 안이지만 심사 노트 여러 곳에 적혔다.
5. **그림이 안 붙는 자리가 남았다.** 만든 쪽 마지막 답에 따르면 표(`table`·비교 표) 칸 안의 이모지와, 번호 없는 카드(색 머리띠) 제목의 이모지는 그림으로 그려지지 않고 지워진다.
6. 표·작은 이름표 글씨가 작다는 평은 이번에도 남았다(가독성 3.85가 네 항목 중 가장 낮다).
7. 기관 보고 디자인은 「남색 표 위주라 단조롭다」는 평이다(4.00).

## 4. 확인하지 못한 것 (그대로 믿으면 안 되는 부분)

- **실제 PowerPoint로 열어 보지 않았다.** 이 PC에는 PowerPoint도 LibreOffice도 없다. 모든 그림은 pptx 파일을 읽어 브라우저로 그린 근사 미리보기다. **이모지 그림은 글자(글꼴 Segoe UI Emoji 지정)라서, 실제 PowerPoint에서 색 이모지로 나오는지, 오래된 버전에서 흑백이나 빈 네모로 나오는지, Mac에서 어떻게 바뀌는지는 확인하지 못했다.** 미리보기에서는 색 이모지로 나온다. 이번 라운드에서 가장 먼저 눈으로 확인해야 할 부분이다.
- 웹 슬라이드에서는 이모지가 낱말 앞에 글자로 다시 붙는다. 점검(`check_page`, `slides_review`)은 한 덱에서 통과했지만 눈으로 심사하지 않았고, 크레파스 색·색 타일·큰 정답 장은 PPT 쪽에만 넣었다(색은 웹도 같은 값을 쓴다).
- 주제 5개, 주제마다 실행 2번, 심사 2번이다. +0.06은 「같다」로 읽어야 한다. 맞대결도 같은 쌍을 두 번 본 것이라 독립된 20번이 아니다.
- 기관 보고는 주제 1개, 실행 2번뿐이다. 두 번 다 예산 표가 들어갔지만, 그것이 새 알림 덕인지 요리법 문장 덕인지 우연인지는 가르지 못한다. 두 실행 모두 `"request"`를 적었고 `"omit"`은 쓰지 않았다. 알림 줄이 실제로 떴다가 고쳐졌는지는 실행 기록에서 확인하지 않았다. 알림 자체가 빠진 내용을 잡는 것은 단위 시험으로만 확인했다.
- 꼭 담을 내용 점검은 낱말 맞추기다. 「예산」이라는 말 없이 금액만 쓴 표는 놓칠 수 있고, 낱말만 있고 내용이 빈 장은 통과한다.
- 일반 AI의 「고려의 건국」 덱은 지난번 파일이다. 새로 만들면 달라질 수 있다.
- 심사위원은 한 모델(Opus)이고 그림만 봤다. 만드는 쪽은 Sonnet 하나다.
- 템플릿·사용자 색을 준 경우는 단위 시험만 했다(그림 타일을 쓰지 않음, 큰 색 면 없음, 사용자 색에 우리 색을 더하지 않음).
- 평가 전에 평가 밖 덱(지난번 주제 「흉내 내는 말」을 손으로 쓴 spec)으로 모양을 두 번 그려 보고 고쳤다. 평가에 쓴 18번은 그 뒤 커밋한 코드다.
- 무대·미사일(레거시 스킨)은 건드리지 않아 `studio.py fire` 재생성은 하지 않았다.
